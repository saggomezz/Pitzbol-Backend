2. Diagnóstico Actualizado — Por qué persiste el 525

🔬
Diferencia clave entre modos Cloudflare:
• Full (strict): Cloudflare → Nginx por HTTPS, exige cert válido en origen.
• Full: Cloudflare → Nginx por HTTPS, acepta cert autofirmado en origen.
• Flexible: Cloudflare → Nginx por HTTP plano, no requiere SSL en origen.

Si cambiar de Full Strict a Full no cambia nada, significa que Nginx no tiene ningún listener SSL activo en puerto 443. No es cuestión del certificado — es que el puerto HTTPS no está abierto en el servidor de origen.

3. Solución Definitiva

🔴 Opción A — Cloudflare "Flexible" (solución inmediata, 2 min)

Cambiar el modo SSL en Cloudflare a "Flexible". En este modo, Cloudflare se comunica con el servidor origen por HTTP plano (no HTTPS). No se requiere ningún cambio en Nginx.

Ruta: Cloudflare Dashboard → tu dominio → SSL/TLS → Overview → seleccionar Flexible

⚠️ Limitación: La conexión Cloudflare↔Nginx no estará cifrada. Solo es apropiado si el servidor está en una red privada o como solución temporal.

⚠️ Opción B — Configurar SSL en Nginx (solución correcta, ~15 min)

Instalar un Certificado de Origen de Cloudflare en Nginx y añadir un bloque server que escuche en el puerto 443.

Pasos:

  1. Cloudflare → SSL/TLS → Origin Server → Create Certificate → descargar .pem y .key
  2. Subir ambos archivos al servidor: /etc/nginx/certs/
  3. Añadir en nginx.conf el bloque SSL (ver abajo)
  4. nginx -t && systemctl reload nginx
  5. Mantener Cloudflare en modo "Full" o "Full (strict)"

Configuración Nginx requerida (Opción B)

# Agregar a nginx-pitzbol.conf — bloque para api.pitzbol.me
server {
  listen 443 ssl;
  server_name api.pitzbol.me;

  ssl_certificate /etc/nginx/certs/cloudflare-origin.pem;
  ssl_certificate_key /etc/nginx/certs/cloudflare-origin.key;
  ssl_protocols TLSv1.2 TLSv1.3;

  location / {
    proxy_pass http://localhost:3001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_cache_bypass $http_upgrade;
  }
}
